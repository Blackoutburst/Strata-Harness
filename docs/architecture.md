# Independent supervisor, intermittent model

Ubuntu owns the daemon, SQLite journal, Board identity, coding process and bounded
validation jobs. The personal PC owns Strata inference. The harness never starts,
restarts or changes Strata or its authentication. For the first pilot, the Mac still
owns the local Board and silent emulator, reached through scoped private forwards.

## Runtime components

`supervisor.run` constructs `runtime.Runtime` and the selected `execution.from_config`
factory. Without an operator-selected task it only polls its own addressed inbox
and backend availability. The daemon stays running when inference is unavailable.

The Board client verifies the paired owner/device/agent/session/profile. A local
immutable admission binds one authorized ticket, thread, baseline and workspace.
`TaskLease` serializes versioned claim/renew/release intentions. `Journal` atomically
saves inbox pages/cursor, canonical hash-checked bodies and delivery stages. Empty
polls and routine five-minute renewals do not use the model. Uncertain mutations
fence further effects until reconciled; lease age never proves process cleanup.

The coordinator polls addressed inbox at 30-second intervals and services control
before coding admission. Only the selected task's canonical messages are fetched.
Author checks accept the owner or exact configured manager within that scope.
Guidance is queued at the engine's next safe tool/model boundary. Exact assistant
acknowledgement is separate from semantic application. The checkpoint probe has an
explicit observable application receipt; ordinary prose needs independent review.
Urgent authenticated pause/stop bypasses model availability and checkpoints owned
work after process/validation cleanup.

The selected OpenCode1.19.3 v1 engine has a private home/config and process-group
ownership. RTK is enabled and representative actual rewrites are verified. It gets
only a scoped model-proxy token and validation-gateway token, never the Board,
SSH or real Strata credential. The native-tool plugin constrains paths and a fixed
bash grammar. Android builds run separately in an offline bubblewrap namespace
with only the selected workspace, owned caches and read-only SDK/JDK. Build
controls require reviewed hashes, and successful builds/APKs bind to actual source
content, including across commits. Complete raw failure logs retain exit status.

The owning-host bridge admits only hashed selected APKs and fixed runtime scenarios
for silent caregiver35/emulator-5556. It verifies exact emulator process/AVD,
unlocked state, installed CE storage and resolvable target activity. Tests have a
300-second per-test and 1500-second connected cap. The bridge restores its exact
owned VM snapshot and compares settings, Dialer role and target permission flags.
Cleanup failure fences future work. No raw remote shell/ADB/device selection API is
exposed. Failure screenshots are captured before rollback and retrieved by owned
request ID/hash; the engine's actual image path was tested against served Strata.

## Task lifecycle and limits

`selected -> prepare owned engine -> versioned claim -> develop/build/test -> review -> stop/release`

The first build must start early. Actual source hashes and validation receipts mark
progress; repeated unchanged actions, repeated failures or an omitted build cause
one actionable addressed manager escalation. Validation pauses and the current
session waits at most660seconds. Authenticated guidance can resume the same session
after cleanup. The tested post-pilot policy separately permits at most three
distinct build-file review pauses and three failure pauses; a fourth in either
lane stops the worker. Only the validation adapter's actual unapproved hash request
uses the review lane; a developer's blocker prose cannot select it. Both lanes
still need manager guidance, retain the 660-second deadline and preserve exact-hash
approval. Older journals conservatively retain their consumed failure count.
This policy is not deployed: the first pilot used one shared allowance and stopped
after its fourth escalation. A policy upgrade never resumes that stopped attempt.

Time/step caps or wait expiry terminate the pilot;
there is no automatic second attempt. Normal review requires a clean exact local
commit and a successful build for its current source. Review is not acceptance.

A model outage preserves cursor, pending guidance, session/worktree and receipts.
Board control keeps running. Claim grace is bounded, then verified quiescence and
cleanup precede release. A restart reconciles process fingerprint, global lock,
engine session, claim/version and external effects. An uncertain tool/job or
changed identity cannot be blindly replayed. Real task-level restart/offline
behavior remains an explicit pilot observation beyond the fake-service tests.

## Exclusivity and deployment

The user systemd unit with linger is installed/enabled on Ubuntu. Its process lock
prevents duplicate supervisors for the same state. An owned coding lock protects
Ubuntu, while a live scoped Mac bridge reservation holds the shared Mac worker
lock and is verified before admission/continuation. Prior coding processes were
checked absent before cutover. This is explicit two-host reconciliation, not a
new distributed mutex service. A different host/worker needs a fresh reconciliation;
never copy manager credentials to create a developer.

## Evidence and acceptance

119 fake-service/process tests pass on macOS and Ubuntu; the deployed pilot ran
the preceding 115-test version. Actual Ubuntu engine/RTK,
command failure/boundary, Strata tool/image/usage, offline build and emulator
failure/rollback receipts are in `verification/`. The full baseline instrumentation
smoke failed its generated package-name assertion, and the denied baseline fixture
had no marked tests; neither is a Phone pass. Earlier failed cold starts and setup
attempts are retained. One fresh Phone pilot measures real coordination latency,
renew/inbox cadence, accepted journeys, errors, active and validation time,
input/output/cache tokens and manager review effort. It is independent of the
closed model benchmark. Energy remains unmeasured without real telemetry.

The manager independently reviews every app change, meaningful accessibility and
journey assertions, owned test data and minimal production seams. Failed code stays
isolated. Privileged APK deployment, CI, physical ROM/device and SIM acceptance are
separate gates; no production merge follows merely from a harness run.
